# 开放世界 NPC 交谈与性格指令任务报告

完成第一项：玩家可以在开放探索中遇见 NPC，向他打招呼或聊一个话题；分开后再见，NPC 会记得此前见过谁、聊过什么。汤姆·里德尔和赫敏·格兰杰使用同一套交谈与存档逻辑，不需要完成铜鸟支线，也不需要 AI Key。

## 玩家怎么试

1. 用里德尔时代角色完成第一堂魔咒课。第一周周一午餐，从魔咒教室前往大礼堂，打开「场景 → 此地角色」，点击**汤姆·里德尔**。交谈本身不消耗时段。
2. 在「地点」频道输入 `和汤姆聊聊咒语笔记`，也可以输入 `/npc 汤姆：笔记`。第一次讨论时他会提出一个练习办法，再问时会追问上次的练习。其他场景或时段输入相同内容会给出去哪找人的提示。
3. 晚餐结束后，在「自由活动」时段去图书馆再找他。用同一角色退出重进，再在他出场的时候交谈，仍会得到熟人招呼和重复话题的后续台词。哈利时代的角色不会遇到汤姆，但可以在午餐或晚饭后的自由活动时段去图书馆找赫敏。

## 性格指令与内容包

`src/resources/story/worlds/npcs/` 保存同时代世界包配套的 `campus-npc/v1` 数据。NPC 卡分开定义三件事：

- **性格指令**：`persona.traits`、`persona.speech`、`persona.boundaries` 分别写性格、说话方式和行为边界；`sources` 可选，只供创作者查证。代码可通过 `Persona::instructions()` 取得合并后的中英文指令。
- **出现与识别**：`id` 使用 `时代.角色`，`aliases` 支持简称，`appearances` 用场景 ID 和学期时段指定何时在场。时段沿用学期系统：`0` 早餐、`1` 上午、`2` 午餐、`3` 下午、`4` 晚餐、`5` 自由活动、`6` 夜间。
- **离线交谈**：首次招呼、熟人招呼、未知话题的引导、话题初次和重复回应均为中英文内容。当前游戏读取预写台词；性格指令是给创作者和未来 Agent 用的，不会发到模型 API。

汤姆的人物卡参考了[官方人物档案](https://www.harrypotter.com/fact-file/characters-and-pets/lord-voldemort)和[官方角色分析](https://www.harrypotter.com/features/analysing-tom-riddles-choices)：把在校时期的聪明、野心与善于隐藏动机转成扮演约束。赫敏的人物卡依据[官方人物档案](https://www.harrypotter.com/fact-file/characters-and-pets/hermione-granger)中的好学、勇气与解决问题的能力。出场安排、具体措辞和玩家互动都是游戏原创设定，不是原著事件或原文。

## 自定义 NPC 导入与三时代角色卡

本地存档角色可以从「系统 → 导入或替换自定义 NPC」选择一个 `campus-npc/v1` JSON。可从 [里德尔时代模板](../examples/custom_npcs_riddle.json)复制一份，改角色名、别名、`persona`、出现地点和台词。模板中的角色在晚饭后的自由活动时段出现在图书馆，可输入 `/npc 里德：怀表`。

- `era` 必须与当前角色的存档时代一致；原创角色使用 `时代.custom_名字` 形式的稳定 ID。改显示名不需要改 ID；保持 ID 和话题 ID 不变，之前见面和讨论的事实还能被读到。
- `custom_fields` 可选，最多 24 个字段。字段名用小写字母、数字和下划线，以字母开头；值支持字符串、整数、布尔值或 `{"zh":"…","en":"…"}`。这些字段会保留给未来的 Agent 读取，**不会自动变成判定规则、权限或模型指令**。
- 当前每角色、每时代保存一份本地自定义包，最多 32 张卡、256 KiB。重新导入会替换该角色的整份自定义包，因此要把仍想使用的原创 NPC 一起放进新文件。无效包不替换，角色 ID 与内置角色同名或别名冲突也会被拒绝。文件在本地存档目录的 `npc-packs/<角色 ID>/<时代>.json`，不上传、不改原著卡。MySQL 开发模式不支持导入。
- 已纳入 21 张时代版本卡：哈利入学阶段 10 张、亲世代 6 张、里德尔时期 5 张。这是当前校园开局的主要阵容，不是整套系列的人物百科；未把后续才入学或出场的角色提前安排进首周。学生和教授版斯内普、学生和看守版海格、教授和校长版邓布利多分开处理。莉莉在校时使用伊万斯，桃金娘在里德尔时代的本作开场仍是活着的学生。性格事实有官方参考，台词、行程和即时回应是原创，不把后来的事件当作当前已知情节。

Agent 将来可生成同一份 JSON，交给 `Catalog::loadCustomPack` 校验，再由 `CustomNpcStore` 和客户端保存、加载。不需要改 TaleState 世界包格式。这个接口目前是 JSON 导入，尚无可视化表单或模型生成。

## 代码与存档

- `src/application/open_world/npc/NpcCatalog.*` 校验人物卡、解析双语指令并按学期时段判断在场情况。`NpcInteraction.*` 处理交谈和记忆，控制器只把当前角色、时代、场景和时段传进去。
- 场景抽屉和文字指令进入同一个交谈入口。识别出的 NPC 指令优先在本地处理，包括不在场时的提示，不会送进玩家聊天室；聊天协议、对角巷和主线运行时未改。
- 继续用 `npc_memories`，按 `character_id + npc_id` 保存 `met` 与 `discussed_spell_notes` 等事实，不新增数据库表、不往学期存档重复写。提交成功才显示台词；相同话题不重复写入，也不增加好感。旧章节沿用原 NPC ID。

## 验证与边界

Windows Qt/MinGW 完整构建成功。16 项非联机 CTest 测试通过，现有 Qt TCP 回环测试单独运行通过，共 17 项。

NPC 测试覆盖内容加载与校验、双语输入、时代／地点／时段限制、重复交谈、不同角色隔离、存档失败、关闭并重新打开 SQLite 后的记忆恢复。场景抽屉测试覆盖动态名单、空场提示和点击人物发出正确 ID。

自定义包测试覆盖模板导入、类型检查、错误时代、原著 ID 与别名冲突、不存在的场景、导入不成功时保留旧内容、不同角色间隔离，以及更改名字后按原 ID 恢复记忆。原著角色卡检查三个时代的来源和双语指令，并测试同名斯内普按当前时代解析。

本次没有制作固定友谊线、恋爱、送礼或刷好感。联机玩家不共享 NPC 私人对话和记忆。建议下一步给同一个话题增加两种有意义的玩家回应，并让 NPC 对不同选择记住不同事实，再决定哪些内容值得交给生成 Agent。
