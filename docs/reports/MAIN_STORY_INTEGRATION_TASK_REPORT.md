角色创建

本次没有实现完整文字开放世界，也没有把 TaleState 源码直接复制或硬链接进项目。主线终点已经形成稳定的状态交接契约，下一阶段可以围绕这份契约讨论并实现两个仓库的适配。

## 玩家体验变化

1. 玩家在霍格莫德车站跟随新生后，不再停在“已解锁分院”的半成品状态，而会自动进入黑湖章节。
2. 黑湖、前厅、分院帽和学院长桌全部进入正式中央叙事流。
3. 地点面板和角色状态面板会同步显示四个新场景及“乘船”“等待分院”“参加分院”“自主探索”等状态。
4. 分院结果继续读取角色档案，四学院得到不同评价，不会覆盖玩家创建角色时的学院。
5. NPC 记忆和好感从对角巷、站台与列车一直延续到黑湖和礼堂。
6. 在学院长桌坐下后，中央叙事框显示明确的“新生序章完成”和“自主探索已经开放”提示。
7. 固定剧情选项被清空，输入提示切换为“描述你想探索的地点、角色或行动……”。
8. 登录恢复已完成的主线时，不会重新出现过期的分院选项，而会重新进入自主探索状态。

## 代码改动

### 战役编排

- `StoryCampaignService` 正式注册 `sorting_ceremony`，内置战役由两章扩展为三章。
- 霍格莫德结尾由单纯 `unlock_chapter` 改为事务内 `transition_to_chapter`。
- 只有旅程完成提交成功后，控制器才会启动分院章节。

### 主线完成事件

- `StoryRuntimeService` 新增通用 `chapterCompleted(chapterId)` 信号。
- 信号只在章节由未完成变为完成、且事务已经提交和事件已经发布后触发。
- 控制器只把 `sorting_ceremony` 的完成解释为新生主线终点，其他章节不受影响。

### 自主探索交接

分院最终动作原子写入：

- `main_story_complete`：固定新生主线已经结束；
- `open_world_handoff_ready`：权威状态已经可以交给未来开放世界适配器；
- `house_table_reached`：玩家当前叙事锚点位于学院长桌；
- `first_night_at_hogwarts`：未来可用的结构化剧情锚点。

完成后 `CampusController` 停止固定章节运行时、清空剧情按钮，并把中央输入交还给当前校园自由输入逻辑。这样玩家输入不会再收到“章节已经完成”的错误。

### UI 与本地化

- 新增黑湖渡船、礼堂前厅、分院帽前和学院长桌地点映射。
- 新增布兰布尔先生、副校长和分院帽的显示名称。
- 新增五种旅程/完成状态的中英文文本。
- 新场景仍使用现有中央叙事框，没有创建第二套剧情 UI。

## TaleState 后续联动边界

参考 `talestate-cpp` 当前公开设计，两个项目共同遵守：Agent 负责理解自由输入并提出候选行动，C++ 负责权威状态裁决，状态变化通过 Delta 原子提交，叙述只能依据已经提交的事实。

下一阶段适配建议从以下输入开始：

```text
触发条件：main_story_complete && open_world_handoff_ready
角色事实：学院、魔杖、宠物、金币、背包
世界位置：house_tables
关系事实：NPC 好感与记忆
剧情事实：已完成章节、已解锁锚点、事件日志
```

TaleState 返回的移动、交谈或事件候选不能直接写数据库；应先翻译成当前项目可验证的命令/Delta，再复用现有事务提交与中央叙事发布顺序。本轮只确立这条边界，没有添加新依赖或网络调用。
