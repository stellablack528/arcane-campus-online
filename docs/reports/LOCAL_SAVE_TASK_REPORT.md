# 零配置本地存档任务报告

## 玩家体验

没有 `database.ini` 时，客户端首次启动自动创建本地 SQLite 存档和游戏必需的房间、物品。玩家直接点击“创建新生角色”，从对角巷开始；后续剧情行动、金币、背包、NPC 记忆均使用现有事务保存。退出后用用户名与学院继续。

已有 `database.ini` 或显式设置 `ARCANE_DB_CONFIG` 时，仍连接原来的 MySQL 开发库。配置存在但连接失败会显示错误，不会悄悄切换到另一份空白本地存档。两种数据库之间目前没有自动迁移。

## 实现

- `SqliteDatabaseDriver` 接入现有 `DBConnection`/DAO 接口。参数绑定、事务和查询结果仍通过同一抽象层；本地事务使用 `BEGIN IMMEDIATE`。少量现有 MySQL 方言的锁查询和 upsert 由 SQLite 驱动转换。
- `local_save_v1.sql` 定义本地表与最小游戏数据；`LocalSaveBootstrap` 以事务执行幂等初始化。存档放在 Qt 的本地应用数据目录，可通过 `ARCANE_LOCAL_SAVE_DIR` 指定其他目录。
- 构建默认需要 Qt6 Sql 与 SQLite 插件；MySQL C API 头文件变为可选。原 MySQL 路径保留。
- 登录页明确显示自动存档状态；存储启动失败时给出原因，不进入没有剧情存档的演示校园。

## 验证

- 本地存档测试调用真实新生注册服务，覆盖首次初始化、角色和魔杖写入、对角巷购书与金币扣除、剧情事务及 NPC 记忆；关闭连接后重新打开，验证登录、当前店铺、背包和剧情进度均被恢复。
- 不提供 MySQL 头文件的独立构建与本地存档测试通过。
- 客户端隐藏启动检查确认自动生成 `campus.sqlite`。
- 完整 CTest 13/13 通过。

## 当前边界

这是单机角色与剧情存档。校园联机聊天仍由独立服务端负责，尚未把剧情裁决迁到服务端；MySQL 旧存档不会自动导入 SQLite。
